## 安全修复分支的兼容性说明

以下说明适用于 `security-audit-boundaries` 分支，尚未发布。

- 数据库自动补充评论的 `guest_token_hash`（默认空字符串）和邮件验证码的 `attempts`（默认 0）。早期开发构建的 `guest_key_hash` 列会自动改名并保留归属，评论缓存会重新填充。重复迁移不会重置已有凭证或尝试次数；这两个字段不作为公开评论或用户 API 字段。
- 匿名凭证只绑定携带凭证新建的评论，不凭昵称或邮箱认领历史评论。旧客户端仍可提交评论、无感创建页面和统计 PV，但查看私有待审评论及通知需要有效登录或新客户端持有的匿名凭证。清除浏览器存储、换浏览器后，匿名凭证不能自动恢复。
- Artrans 导入导出继续使用原有内容格式，不携带匿名凭证归属。若迁移后需要保留这种归属，应使用完整数据库备份，并保持浏览器中的后端地址及凭证存储一致。
- 页面列表 API 的 `has_comments` 参数保持可选，省略时保留原有全量列表。认证配置响应的 `callback_origin` 也为可选字段；新认证插件在旧后端未返回它时回退到登录入口域名。独立回调域名部署应同步升级后端与认证插件。

旧程序可以忽略新增列，但回退到未修复版本会重新引入原有权限问题；数据库格式兼容不等于安全修复可以回退。

## 命令行一键升级

执行 `./artalk upgrade`

此操作会从自动从 GitHub Release 下载并升级程序，执行前需关闭 Artalk。

:::tip

执行 `./artalk upgrade -f` 携带参数 `-f` 执行强制更新。

:::
